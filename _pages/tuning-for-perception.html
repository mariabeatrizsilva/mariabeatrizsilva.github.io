TAA ships in nearly every modern game engine, yet its parameters are still tuned by trial and error. We measured which ones actually change what viewers see, and found that one parameter does almost all the work.

Abstract

Temporal Anti-Aliasing (TAA) is a highly successful image-space reconstruction technique in real-time rendering and has become a standard component of modern game engines. While recent real-time reconstruction methods have achieved substantial practical success, the perceptual principles underlying temporal anti-aliasing and related reconstruction techniques remain poorly understood, limiting the development of more principled approaches. A better perceptual grounding of TAA could help direct computational resources toward factors that most strongly influence perceived visual quality. In this work, we present a systematic study of how TAA parameters affect perceived visual quality across a diverse set of scenes and rendering resolutions. We used Unreal Engine to render 20 scenes across 4 resolution levels and 28 parameter configurations, producing a representative 2,240 video dataset of TAA artifacts. We evaluated the dataset against a 16× supersampled reference using CGVQM, a perceptual video quality metric designed for computer graphics content. Our results reveal that TAA’s perceptual impact is strongly dependent on the rendering resolution and that among the four parameters studied, the temporal accumulation factor has a substantially larger effect on perceived quality than the others, with this effect becoming more pronounced at lower rendering resolutions. We provide an in-depth analysis of this new dataset, including an analysis of compute-quality tradeoffs for the studied parameters, along with a lightweight computational model that can accurately predict our empirical findings. We demonstrate how this model can be used to optimize default TAA parameters or for real-time performance-quality optimization in video games.

A dataset of TAA artifacts

We rendered every scene in Unreal Engine 5.6 at four internal resolutions and swept each TAA parameter independently, holding the others at engine defaults. Each render is a 5-second, 1080p, 30 fps sequence, saved as lossless PNG frames so that compression doesn’t confound the quality scores. Each one is scored against a 16× supersampled reference with CGVQM, a perceptual video quality metric calibrated on rendering artifacts.

What we found

1

One parameter does almost all the work

The alpha weight (how much the current frame contributes to the accumulated history) dominates perceived quality. Tuning it away from Unreal’s default of 0.04 moves scores by +2.02 to −5.09 CGVQM points on average. History-buffer resolution has a modest effect. Filter size and jitter sample count barely matter: their score ranges stay at or below 0.3 points at every resolution.

2

It matters more the lower you render

Most games run TAA below native resolution and upsample, and that is where the choice of alpha weight matters most. Its quality range more than doubles from native to 25% resolution. The best value also moves: lower resolutions favor stronger accumulation (α ≈ 0.2), while near-native resolutions favor more of the current frame (α ≈ 0.5–0.6).

3

Better quality at no extra cost

The TAA pass takes under 0.08 ms per frame, and changing alpha weight, filter size or sample count adds no measurable GPU time. Moving alpha weight to its resolution-optimal value improves quality over Unreal’s default by up to 9.88%, essentially for free. The gain is scene-dependent, though: it ranges from 0.13% to 9.88%. That points toward content-adaptive tuning rather than a single new default.

A lightweight quality model

For each parameter, we fit a six-term model that predicts CGVQM quality from render resolution R and parameter value v:

𝓜(R, v) = k1 + k2 log R + k3 log v + k4 vR + k5 v + k6 R

The model fits the measured data closely: for alpha weight, RMSE = 0.38 CGVQM points (on a 0–100 scale) with Pearson r = 0.993. Because it is cheap to evaluate, it can run inside a renderer’s frame loop.

Dynamic resolution scaling

When the engine drops resolution to hold frame rate, the model gives the quality-maximizing alpha weight for that resolution in closed form.

Visually lossless rendering

Given a target quality, a search over the model finds the lowest resolution, and the alpha weight to pair with it, that still meets the target. This saves compute without visible loss.

Ongoing work

1

Optimizing parameters jointly

This study varies one parameter at a time around Unreal’s defaults. That isolates each effect but can hide interactions: filter size and sample count may matter little only because alpha weight was held at 0.04, where history already absorbs most subpixel variation. We are now searching the joint parameter space to find configurations that one-at-a-time sweeps cannot reach.

2

Content dependence, in depth

Sensitivity to alpha weight and history resolution tracks scene texture, spatial detail and temporal activity. With 20 scenes, though, these trends are suggestive rather than conclusive. We are expanding the scene corpus and moving from per-video to per-region and per-frame content features, such as motion-vector statistics, so that tuning can respond to what is on screen.

3

A better quality model

The current model is fit separately for each parameter from resolution alone. Next, we are building a single predictor over all parameters, resolution and content features. We are comparing parametric fits with more flexible learned models, and we evaluate on held-out scenes so the model has to generalize to content it has not seen.

Throughout, quality comes from CGVQM, a metric calibrated on rendering distortions. Because the method is metric-agnostic, a subjective user study can validate the key findings against real viewers.
